# 인증·운영진 코드 — v10

이 문서는 `sai-room-backend`의 구현에 해당합니다. 체험 계정·브라우저 저장소 인증을 사용하지 않습니다. 서버는 하나의 동아리를 관리합니다.

| 계정 | 사용 범위 |
| --- | --- |
| 미로그인 | 로그인·가입 |
| 승인 대기·거절 | 본인 승인 상태·로그아웃 |
| 승인된 멤버 | 동방·예약·게시판·본인 문의·내 공 |
| 승인된 운영진 | 멤버 기능 + 전체 문의·답변 + 가입 코드 변경 |
| 승인된 관리자 | 운영진 기능 + 회원 승인·거절 |

회원가입 요청에는 임의 role/status를 허용하지 않습니다. 코드가 없으면 member, 서버에서 유효성을 확인한 경우 operator로 신청하며 항상 pending입니다. 코드로 admin을 생성하지 않습니다. 최초 관리자는 서버의 `create_admin.py`로만 설정합니다. 기존 계정의 PBKDF2 파생값은 그대로 검증하고 신규 비밀번호는 PBKDF2-SHA256 600,000회로 저장합니다.

## 코드 변경

초기 코드는 첫 실행 때 안전한 난수로 생성하거나 `SAI_INITIAL_OPERATOR_CODE`에서 읽습니다. DB에는 salt가 포함된 파생값만 저장합니다. 자동 생성한 원문은 DB 옆의 `.initial-operator-code` 파일(600)에 저장하며 웹에서 제공하지 않습니다. 배포할 때 이 파일·DB·실제 환경변수를 소스 저장소에서 제외합니다.

앱의 코드 변경은 현재 비밀번호와 코드 버전이 필요합니다. 서버가 승인된 operator/admin인지 확인하고 변경을 트랜잭션으로 수행합니다. 코드 검증과 가입 생성도 같은 DB 쓰기 트랜잭션 안에서 수행해 변경과 가입이 순서대로 처리됩니다. 변경된 이후의 요청에는 이전 코드가 통하지 않습니다. 코드 변경이 기존 승인/대기 계정을 취소하지는 않습니다.

코드 원문을 조회하지 않으므로 새 코드가 필요한 경우 운영진에게 전달받거나 운영진이 새로 변경해야 합니다. 감사 기록에는 행위자 ID·변경 종류·시각만 저장합니다. 비밀번호/코드 원문은 저장하거나 API 오류에 반사하지 않습니다. 서버 재시작은 코드를 되돌리지 않습니다.

## 세션과 접근 제어

동일 출처 `HttpOnly`, `SameSite=Strict` 쿠키를 사용합니다. production은 `__Host-` 접두사와 Secure가 적용되고 HTTPS 공개 주소 설정이 필수입니다. 브라우저 스토리지에 세션 토큰을 저장하지 않습니다. 세션은 8시간, 로그인 전 CSRF 세션은 30분입니다. 로그인 때 세션 ID를 교체하고 로그아웃 때 DB 세션을 제거합니다.

변경 요청은 CSRF와 Origin/Sec-Fetch-Site를 확인합니다. 로그인·가입·코드 변경 횟수를 서버 DB에서 제한합니다. 일반 저장 요청에는 사용자별 Idempotency-Key를 사용하고 같은 키의 다른 요청은 거절합니다. 인증 및 코드 변경 요청의 비밀번호/코드는 프론트 재시도 키 캐시에 보관하지 않습니다.

API에서 세션의 현재 회원 상태와 역할을 다시 읽고, 문의·예약·이미지에 소유권을 검사합니다. 회원에게 다른 회원의 문의를 전송하지 않습니다. 익명 공은 서버에서 이름을 ‘익명 회원’으로 바꿉니다. 비공개 문의의 작성자와 승인 목록의 이름은 공 익명 설정과 별도의 권한 범위입니다.

## 기존 데이터

기존 `users`·`reservations`·`posts`·`comments`를 삭제하지 않고 필드를 추가합니다. 기존 아이디로 로그인할 수 있고 신규 회원은 이메일을 사용합니다. 기존 작성자를 식별할 수 없는 예약·공개 글은 유지하되 임의로 현재 회원에게 소유권을 배정하지 않습니다. 기존 무인증 API는 새 앱에서 등록하지 않습니다. 이전 Bearer 세션은 새 쿠키 세션으로 간주하지 않으므로 다시 로그인해야 합니다.

업데이트 전 서버를 멈추고 DB를 백업하세요. 메일 인증·비밀번호 재설정·관리자 권한 승격 UI는 포함하지 않습니다.
