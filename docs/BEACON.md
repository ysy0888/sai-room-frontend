# 비콘 자동 입퇴실 연결

현재 제공하는 것은 **네이티브 앱용 서버 API와 웹의 연결 상태 화면**입니다. iOS/Android 감지 모듈, 앱 설치 패키지와 실물 비콘 연동은 아직 구현·검증하지 않았습니다. 운영 서버에서는 `SAI_BEACON_ENABLED=false`가 기본이며 실제 인원 집계는 수동 입퇴실을 계속 사용합니다. 웹이나 홈 화면에 추가한 웹앱만으로 휴대폰 화면이 꺼진 뒤 비콘을 상시 감지하지 않습니다.

## 동작 구조

동방의 상시 전원 iBeacon → 회원의 네이티브 앱이 영역 진입·이탈 감지 → 회원 기기에 발급된 입퇴실 전용 인증으로 서버 전송 → 기존 인원·공 표시 갱신.

비콘은 식별 신호를 송신합니다. 비콘 자체가 회원 계정이나 휴대폰의 주인을 식별하지 않습니다. 각 회원이 설치한 앱이 로그인 계정과 감지 이벤트를 연결합니다. 계정을 만든 것만으로 시작되지 않으며 승인된 회원의 명시적 자동 감지 동의와 OS 권한이 필요합니다.

- iOS: Core Location의 iBeacon region monitoring, 앱 생명주기 복원, 위치 권한·백그라운드 설정. 지속적인 ranging이나 웹 JavaScript 타이머에 의존하지 않습니다.
- Android: 필터를 설정한 BLE `PendingIntent` 스캔 또는 적합한 네이티브 비콘 라이브러리, OS 버전에 따른 위치/주변 기기 권한, 백그라운드 실행 정책 대응. 이탈 판정은 실제 기기에서 검증해야 합니다.
- 강제 종료, Bluetooth/권한 해제, 절전, 네트워크 단절은 누락·지연을 만들 수 있습니다. 24시간 무중단 감지를 보장하지 않습니다. 웹의 수동 입퇴실을 유지합니다.
- 복도·옆방에서의 오인식, 문 닫힘, 휴대폰 주머니·가방, 여러 기기 동시 진입은 설치 현장에서 송신 출력/배치/판정 기준을 조정합니다. 수신 강도는 정확한 거리나 출석 증명이 아닙니다.

## 서버 설정

실제 비콘의 iBeacon UUID, major, minor를 확인한 뒤 서버 환경변수에 설정합니다. 이 식별자는 비밀번호가 아니며 서버가 허용한 비콘만 처리합니다.

```dotenv
SAI_BEACON_ENABLED=false
SAI_BEACON_UUID=<실제 비콘 UUID>
SAI_BEACON_MAJOR=<0..65535>
SAI_BEACON_MINOR=<0..65535>
```

네이티브 앱과 실물 테스트를 완료하기 전에는 `true`로 바꾸지 않습니다. 잘못된 설정이면 활성화되지 않습니다. 다른 방 비콘은 등록하지 않습니다. 운영 DB는 `sai_private.beacon_devices` 테이블을 먼저 추가하고, RLS와 `sai_runtime` 전용 권한을 적용한 뒤 코드를 배포합니다. 신규 설치 스키마와 권한은 `schema.postgres.sql`, `grants.postgres.sql`에 포함됩니다. 기존 테이블/회원/글/예약은 삭제하지 않습니다.

## API

모든 요청은 HTTPS, 같은 서비스의 `/api/v1`를 사용합니다. 네이티브 앱은 정상 로그인 절차와 서버의 CSRF 토큰을 사용해 기기를 등록합니다. 웹뷰 로그인과 네이티브 HTTP 클라이언트의 쿠키 저장소가 다르면 명시적으로 세션을 연결해야 합니다. 비밀번호나 쿠키를 JavaScript 로컬 저장소로 복사하지 않습니다.

| 요청 | 인증 | 동작 |
| --- | --- | --- |
| `GET /beacon/config` | 승인된 회원 세션 | 활성 상태, 비콘 식별자, 이탈 유예, 기기 연결 상태 |
| `POST /beacon/devices` | 승인된 회원 세션 + CSRF | `{ "platform": "ios" 또는 "android", "consent": true }`로 기기 등록 |
| `DELETE /beacon/devices` | 승인된 회원 세션 + CSRF | 기기 자격 증명 폐기 및 해당 비콘으로 생긴 입실 기록 제거 |
| `POST /beacon/events` | `Authorization: Bearer <deviceToken>` | 본인 계정의 입퇴실 신호만 전송 |

등록 응답은 `{deviceToken, expiresAt, scope: "beacon:presence"}`입니다. 원문은 한 번만 반환되고 서버에는 해시만 보관됩니다. 앱은 Keychain/Keystore에 저장합니다. 계정당 기기 하나만 활성화되며 재등록하면 이전 기기의 토큰은 즉시 폐기됩니다. 새로 관측한 유효 이벤트를 받을 때마다 토큰 유효기간을 30일 연장하므로 정기적으로 이용하는 회원에게 월별 재로그인을 요구하지 않습니다. 30일간 관측이 없으면 만료됩니다. 그때는 네이티브 앱에서 유효한 로그인 세션으로 재등록하고, 세션도 만료된 경우 재로그인을 안내해야 합니다. 등록 응답을 잃었으면 포그라운드에서 다시 등록합니다. 등록 요청을 백그라운드에서 무조건 재시도하지 않습니다.

이 토큰으로 게시판·문의함·회원 목록은 읽을 수 없고, 다른 회원 ID를 요청에 지정할 수도 없습니다. 회원 승인 상태가 해제되면 감지 요청도 거부됩니다. 로그아웃 시 네이티브 감지 중지, 서버 기기 연결 해제, 로컬 토큰 제거를 함께 수행해야 합니다.

이벤트 예시(실제 값은 config 사용):

```json
{
  "eventId": "unique-event-id-at-least-16-chars",
  "roomId": "sai-room",
  "state": "inside",
  "uuid": "비콘 UUID",
  "major": 1,
  "minor": 1,
  "observedAt": 1795392000000
}
```

- `state`: `inside` 또는 `outside`. `observedAt`: 기기가 실제 관측한 Unix 밀리초.
- 이벤트 ID는 UUID 등 매 이벤트 고유 문자열을 사용합니다. 네트워크 재시도에서는 같은 ID와 관측 시각을 유지합니다.
- 2분 넘게 오래되거나 미래인 시각은 거부합니다. 네트워크가 돌아오면 과거 입실을 재생하지 말고 현재 상태를 다시 감지해 새 이벤트를 보냅니다.
- 중복 ID나 마지막 처리 시각보다 이전/동일한 이벤트는 인원을 바꾸지 않습니다.
- 정상 응답 `{accepted: true, state, exitGraceSeconds: 120}`. 중복 응답 `{accepted: false, reason: "duplicate_or_older"}`는 성공적으로 무시된 것이며 재시도하지 않습니다.
- 수동 퇴실 뒤 5분간 `{accepted: false, reason: "manual_override", retryAfter}`. 자동 재입실을 강제로 반복하지 않습니다. 유예 이후 새로 감지된 상태만 전송합니다.
- 401: 토큰 폐기/만료 또는 승인 해제. 감지를 중지하고 앱에서 재연결 안내. 422: 잘못된 식별자/시각/본문을 수정. 429: 요청 제한. 503: 서버 비콘 기능 꺼짐. 무한 재시도하지 않습니다.

## 인원 반영 규칙

1. `inside`는 본인 한 명만 추가하거나 비콘 입실 만료 시각을 갱신합니다. 같은 사람의 공·기존 입실 시각은 유지됩니다.
2. `outside`는 120초 유예 후 퇴실합니다. 그 사이 다시 `inside`를 받으면 퇴실을 취소합니다. 반복 이탈 이벤트가 유예를 계속 늘리지는 않습니다.
3. 비콘 입실은 마지막 유효한 `inside` 이후 최대 12시간 유지됩니다. 앱/권한/네트워크 문제로 이탈 이벤트가 사라져도 영구 재실로 남지 않게 하는 상한입니다. 따라서 12시간 넘는 체류에는 OS가 허용하는 실제 재관측이 필요합니다.
4. 사람이 수동으로 입실한 기록은 비콘 이탈 신호나 연결 해제로 삭제하지 않습니다. 수동 입실의 기존 4시간 만료 정책을 유지합니다.
5. 현재 인원 API가 만료 기록을 정리하며, 화면은 기존 30초 폴링으로 반영합니다. 서버리스 환경의 장시간 타이머나 상시 작업 프로세스에 의존하지 않습니다.
6. 기능을 끄면 새 이벤트를 받지 않습니다. 이미 반영된 비콘 입실 기록은 수동 퇴실·연결 해제 또는 기존 만료 시각에 정리됩니다.

## 출시 전 실제 기기 검증

iPhone/Android 각각 잠금·백그라운드·재부팅·강제 종료·권한 변경·절전·오프라인 복구·장시간 체류를 시험합니다. 출입구와 복도에서 오인식률/반영 지연을 측정하고, 자동 감지 동의와 해제가 작동하는지 확인한 후 기능을 켭니다. 이 저장소의 서버 모의 이벤트 검사는 실제 BLE 수신 테스트를 대체하지 않습니다.

공식 자료: [Apple iBeacon 감지](https://developer.apple.com/documentation/corelocation/determining-the-proximity-to-an-ibeacon-device), [Android 백그라운드 BLE](https://developer.android.com/develop/connectivity/bluetooth/ble/background).
