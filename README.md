# SAI ROOM

동아리방 현황·예약·게시판·운영진 문의를 제공하는 웹 앱입니다. v10부터 체험 계정과 인원 테스트를 제거하고, 동일 출처의 FastAPI 서버와 SQLite에 연결합니다. 프론트 화면만 열거나 Live Server로 실행하면 API를 사용할 수 없습니다.

## 실행

Python 3.12 이상을 사용합니다. 저장소 루트에서:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r sai-room-backend/requirements.txt
# 관리자 계정이 없는 새 설치에서 한 번만 실행
python sai-room-backend/create_admin.py
python -m uvicorn main:app --app-dir sai-room-backend --host 127.0.0.1 --port 5317
```

http://127.0.0.1:5317 에서 사용합니다. Node가 있으면 마지막 서버 실행 대신 `npm run dev`도 가능합니다. HTML·CSS·JS 빌드 결과를 포함했으므로 실행에는 npm 설치가 필요하지 않습니다.

기존 `sai-room-backend/sai.db`가 있다면 **서버를 멈추고 DB를 백업한 후 업데이트**하세요. 기존 계정·비밀번호·예약·글을 보존하는 추가형 마이그레이션을 실행합니다. 기존 관리자는 원래 아이디로 로그인할 수 있습니다. 신규 가입은 이름·학번·이메일·비밀번호(8자 이상)를 사용합니다. 자동 생성되는 관리자나 공용 비밀번호는 없습니다.

## 운영진 코드

- 최초 실행 시 안전한 임의 코드를 한 번 생성합니다. 코드 원문은 서버의 `sai.db.initial-operator-code` 파일에만 저장하며 파일 권한은 600입니다. DB 경로를 바꿨다면 같은 경로 뒤에 `.initial-operator-code`가 붙습니다.
- 사전에 지정한 코드를 사용하려면 서버 환경변수 `SAI_INITIAL_OPERATOR_CODE`를 설정합니다. 최초 설정에만 적용되며, 재시작해도 앱에서 변경한 코드를 덮어쓰지 않습니다.
- 회원가입에서 코드를 생략하면 멤버, 유효한 코드를 입력하면 운영진으로 **신청**합니다. 두 경우 모두 관리자 승인 전에는 앱을 사용할 수 없습니다.
- 승인된 운영진·관리자는 **설정 → 동아리 운영 → 운영진 가입 코드**에서 본인 비밀번호를 확인하고 코드를 변경합니다. 새 코드는 12–128자입니다. 기존 코드는 즉시 무효화되며 이미 가입한 사람의 권한은 바뀌지 않습니다.
- 다른 운영진이 먼저 변경한 경우 덮어쓰지 않고 새로고침을 안내합니다. 코드 원문은 조회 API에서 반환하지 않습니다. 변경 전에 새 코드를 안전하게 보관하고 필요한 운영진에게 직접 전달하세요.
- `.initial-operator-code` 파일은 최초 값의 전달용입니다. 앱에서 코드를 바꾸면 이 파일의 옛 코드는 더 이상 유효하지 않습니다. 최초 전달 후 안전하게 보관/삭제하는 운영 절차를 정하세요.

## 기능

SAI 로고 시작 화면, 쿠키 세션 로그인, 가입 승인·거절, 역할별 문의함과 답변, 예약·게시판 CRUD, 내 공 익명·색상·이미지 설정을 제공합니다. 3D 공과 통, 드래그 회전, 사용자가 허용한 기기 흔들림 반응을 유지합니다.

인원은 **회원이 직접 입실·퇴실한 기록**으로 집계합니다. 입실 기록은 4시간 후 만료되고 30초마다 갱신합니다. 로그인 자체를 입실로 간주하지 않습니다. 자동 비콘 감지·BLE 수신은 구현되어 있지 않습니다. 실제 감지기를 연결할 때는 별도의 신뢰된 수집 API가 필요합니다.

## 운영 서버 배포

서버 환경에 `SAI_ENV=production`, `SAI_PUBLIC_ORIGIN=https://실제-도메인`을 설정하고 HTTPS 역방향 프록시 뒤에서 실행하세요. 프론트와 `/api/v1`, `/media`는 같은 출처를 사용해야 합니다. `.env.example`은 예시이며 자동으로 읽지 않습니다. 배포 시스템에서 환경변수를 주입하세요.

SQLite는 영속 디스크에 보관합니다(`SAI_DB_PATH`로 변경 가능). 이 구현은 단일 동아리·단일 서버 인스턴스 기준입니다. 다중 인스턴스 운영에는 공유 DB와 트랜잭션·제한 정책 이관이 필요합니다. 코드에 서버 주소·비밀 코드·DB를 넣거나 GitHub에 업로드하지 마세요.

인증은 HttpOnly/SameSite 쿠키, 서버 CSRF 검사, 로그인 세션 교체, 서버 승인·역할·소유권 검사와 요청 제한을 사용합니다. 운영 환경에서는 Secure 쿠키가 적용됩니다. 기존 무인증 `/reservations`, `/posts` 및 Bearer `/auth/*` 경로는 등록하지 않습니다. 새 프론트는 `/api/v1/*`만 사용합니다.

**GitHub 업로드와 외부 서비스 배포는 별개입니다.** 이 버전은 로컬 실제 서버로 검증했으며 외부 도메인·HTTPS·메일 발송·비콘·휴대폰 센서 실물 검증은 하지 않았습니다. 계정 확인 메일·비밀번호 재설정은 미포함입니다.

## 검증

```sh
source .venv/bin/activate
pip install -r sai-room-backend/requirements-dev.lock
npm ci
npm run build
npm run typecheck
npm test
npm run test:server
npx playwright install chromium
npm run test:browser
```

브라우저 검사는 임시 DB·테스트 계정을 사용해 실제 FastAPI 인스턴스를 5320 포트에서 띄우고 종료합니다. 운영 DB를 변경하거나 운영 앱에 체험 계정을 만들지 않습니다. 결과 화면은 로컬 `artifacts/`에 생성합니다.

- 서버 검사 13개: 가입 역할, 승인 경계, 코드 변경·이전 코드 무효화, CSRF·세션, 요청 제한, 문의 격리, 예약 소유권·충돌·멱등성, 익명 공, 마이그레이션, 초기 코드 유지
- 프론트 단위 검사 27개, Chromium 실제 서버 연동 검사 28개 통과
- 빌드·타입 검사 통과
