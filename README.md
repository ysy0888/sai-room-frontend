# SAI ROOM

동아리방 현황·예약·게시판·운영진 문의를 제공하는 웹 앱입니다. 체험 계정과 인원 테스트 없이, 동일 출처의 FastAPI 서버에 연결합니다. 로컬은 SQLite, 무료 운영 배포는 Supabase PostgreSQL을 사용합니다. 프론트 화면만 열거나 Live Server로 실행하면 API를 사용할 수 없습니다.

## 실행

Python 3.12 이상을 사용합니다. 저장소 루트에서:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r sai-room-backend/requirements.txt
# 관리자 계정이 없는 새 설치에서 한 번만 실행
python sai-room-backend/create_admin.py
python -m uvicorn main:app --app-dir sai-room-backend --host 127.0.0.1 --port 5317
```

http://127.0.0.1:5317 에서 사용합니다. Node가 있으면 마지막 서버 실행 대신 `npm run dev`도 가능합니다. HTML·CSS·JS 빌드 결과를 포함했으므로 실행에는 npm 설치가 필요하지 않습니다.

**DB 초기화·마이그레이션**: 로컬 SQLite는 서버 시작 시 필요한 테이블을 자동으로 추가합니다(추가형, 반복 실행 안전). 운영 PostgreSQL은 새 설치라면 `schema.postgres.sql`과 `grants.postgres.sql`을 적용합니다([배포 절차](docs/DEPLOY.md)). 이미 운영 중인 DB에는 관리자 계정으로 `psql "$ADMIN_DATABASE_URL" -v ON_ERROR_STOP=1 -f sai-room-backend/migrations/postgres/002_beacon_presence.sql`을 한 번 실행합니다. 적용 전에는 서버가 시작을 거부하며 이 파일명을 안내합니다.

기존 `sai-room-backend/sai.db`가 있다면 **서버를 멈추고 DB를 백업한 후 업데이트**하세요. 기존 계정·비밀번호·예약·글을 보존하는 추가형 마이그레이션을 실행합니다. 기존 관리자는 원래 아이디로 로그인할 수 있습니다. 신규 가입은 이름·학번·이메일·비밀번호(8자 이상)를 사용합니다. 자동 생성되는 관리자나 공용 비밀번호는 없습니다.

## 운영진 코드

- 로컬 SQLite 최초 실행 시 안전한 임의 코드를 한 번 생성합니다. 코드 원문은 서버의 `sai.db.initial-operator-code` 파일에만 저장하며 파일 권한은 600입니다. DB 경로를 바꿨다면 같은 경로 뒤에 `.initial-operator-code`가 붙습니다.
- 사전에 지정한 코드를 사용하려면 서버 환경변수 `SAI_INITIAL_OPERATOR_CODE`를 설정합니다. 최초 설정에만 적용되며, 재시작해도 앱에서 변경한 코드를 덮어쓰지 않습니다.
- 회원가입에서 코드를 생략하면 멤버, 유효한 코드를 입력하면 운영진으로 **신청**합니다. 두 경우 모두 관리자 승인 전에는 앱을 사용할 수 없습니다.
- 승인된 운영진·관리자는 **설정 → 동아리 운영 → 운영진 가입 코드**에서 본인 비밀번호를 확인하고 코드를 변경합니다. 새 코드는 12–128자입니다. 기존 코드는 즉시 무효화되며 이미 가입한 사람의 권한은 바뀌지 않습니다.
- 다른 운영진이 먼저 변경한 경우 덮어쓰지 않고 새로고침을 안내합니다. 코드 원문은 조회 API에서 반환하지 않습니다. 변경 전에 새 코드를 안전하게 보관하고 필요한 운영진에게 직접 전달하세요.
- `.initial-operator-code` 파일은 최초 값의 전달용입니다. 앱에서 코드를 바꾸면 이 파일의 옛 코드는 더 이상 유효하지 않습니다. 최초 전달 후 안전하게 보관/삭제하는 운영 절차를 정하세요.

## 기능

SAI 로고 시작 화면, 쿠키 세션 로그인, 가입 승인·거절, 역할별 문의함과 답변, 예약·게시판 CRUD, 내 공 익명·색상·이미지 설정을 제공합니다. 3D 공과 통, 드래그 회전, 사용자가 허용한 기기 흔들림 반응을 유지합니다.

인원은 **회원이 직접 입실·퇴실한 기록**과 **SAI 모바일 앱이 동방 비콘(HE5)을 감지한 기록**을 회원당 1명으로 합쳐 집계합니다. 직접 입실 기록은 4시간 후 만료됩니다. 비콘 기록은 퇴실 유예시간(초깃값 120초) 동안 갱신이 없으면 제외합니다. 홈 화면은 30초마다 갱신합니다. 로그인 자체를 입실로 간주하지 않습니다. 이 숫자는 앱으로 감지·입실한 회원 수이며 전체 방문자 수가 아닙니다.

## 동방 비콘 자동 감지 · 모바일 앱

- 비콘 감지는 **Android/iOS 앱(Capacitor)**에서만 동작합니다. 웹 브라우저에서는 "사용 불가"로 안내합니다. 앱은 서버의 기존 웹 화면을 그대로 불러오고, 네이티브 플러그인 `SaiBeacon`만 추가합니다.
- 운영진은 비폰 매니저에서 확인한 HE5의 UUID·Major·Minor를 **설정 → 동아리 운영 → 동방 비콘 등록·설정**에 입력합니다. **실제 식별값은 아직 입력되지 않았습니다.** 신호 기준·갱신 간격·퇴실 유예시간·기준 인원은 같은 화면에서 바꿀 수 있고, 초깃값은 테스트용입니다.
- 지원 범위: Android·iOS 모두 **앱 화면이 켜져 있을 때** 지원합니다. 백그라운드·화면 잠금 상태의 주기 전송은 보장하지 않습니다. iOS는 백그라운드에서 감지가 멈추고, 퇴실 유예시간 뒤 인원에서 빠집니다.
- 개발 서버에서는 같은 인터페이스를 쓰는 감지 시뮬레이터를 제공합니다(본인 계정만, 운영 서버는 거절).

```sh
npm ci
SAI_APP_URL=https://실제-도메인 npx cap sync    # 휴대폰 테스트: SAI_APP_URL=http://PC의-LAN-IP:5317
npx cap open android                              # 또는: npx cap open ios
```

식별값 확인, 등록 위치, 실기기 설치, Android/iOS 지원 범위, 동방 내부·복도·화면 잠금·퇴실 검증 순서는 [비콘 안내](docs/BEACON.md)에 정리했습니다. **실기기·HE5 검증은 아직 하지 않았습니다.**

## 운영 서버 배포

Vercel 배포는 루트의 `vercel.json`을 사용합니다. 서울(`icn1`)에 프론트와 API를 함께 배포하고, 데이터는 Supabase Free 서울(`ap-northeast-2`)에 보관합니다. 단계별 절차는 [배포 안내](docs/DEPLOY.md)를 참고하세요.

다른 서버에서는 `SAI_ENV=production`, `SAI_PUBLIC_ORIGIN=https://실제-도메인`, `SAI_DATABASE_URL`을 설정하고 HTTPS 역방향 프록시 뒤에서 실행하세요. 로컬 SQLite 운영 시에는 영구 디스크의 `SAI_DB_PATH`가 필요합니다. Vercel에서는 `SAI_PUBLIC_ORIGIN`을 생략하면 플랫폼의 `VERCEL_PROJECT_PRODUCTION_URL`을 사용합니다. 프론트와 `/api/v1`, `/media`는 같은 출처를 사용해야 합니다. `.env.example`은 예시이며 자동으로 읽지 않습니다. 배포 시스템에서 환경변수를 주입하세요.

PostgreSQL에서는 서버 전용 역할과 비공개 스키마를 사용하고, 예약·입퇴실 등 다단계 쓰기를 트랜잭션 잠금으로 보호합니다. DB 연결 비밀 값·운영진 코드·사용자 DB는 GitHub나 프론트 파일에 넣지 마세요.

인증은 HttpOnly/SameSite 쿠키, 서버 CSRF 검사, 로그인 세션 교체, 서버 승인·역할·소유권 검사와 요청 제한을 사용합니다. 운영 환경에서는 Secure 쿠키가 적용됩니다. 기존 무인증 `/reservations`, `/posts` 및 Bearer `/auth/*` 경로는 등록하지 않습니다. 새 프론트는 `/api/v1/*`만 사용합니다.

**GitHub 업로드와 외부 서비스 배포는 별개입니다.** 이 버전은 로컬 실제 서버로 검증했으며 외부 도메인·HTTPS·메일 발송·실제 HE5 비콘·휴대폰 실기기(모바일 앱 빌드 포함) 검증은 하지 않았습니다. 계정 확인 메일·비밀번호 재설정은 미포함입니다.

## 검증

```sh
source .venv/bin/activate
pip install -r sai-room-backend/requirements-dev.lock
npm ci
npm run build
npm run typecheck
npm test
npm run test:server
npx playwright install chromium
npm run test:browser
```

브라우저 검사는 임시 DB·테스트 계정을 사용해 실제 FastAPI 인스턴스를 5320 포트에서 띄우고 종료합니다. 운영 DB를 변경하거나 운영 앱에 체험 계정을 만들지 않습니다. 결과 화면은 로컬 `artifacts/`에 생성합니다.

- 서버 검사 13개: 가입 역할, 승인 경계, 코드 변경·이전 코드 무효화, CSRF·세션, 요청 제한, 문의 격리, 예약 소유권·충돌·멱등성, 익명 공, 마이그레이션, 초기 코드 유지
- 프론트 단위 검사 29개, Chromium 실제 서버 연동 검사 48개(주간 날짜·예약 시간 변경·기존 공 유지 포함)
- 배포 검사: 운영 쿠키·도메인 제한·상태 확인·일별 SQLite 백업
- PostgreSQL 검사: 제한된 앱 역할로 전체 API 실행, 동시 쓰기 직렬화, 스키마 변경 차단·RLS·공개 권한 검사, v1→v2 비콘 마이그레이션
- 비콘 서버 검사: 서로 다른 회원 2명=2명, 반복·다중 기기 1명 유지, 유예시간 후 제외, 잠깐 끊김 시 출렁임 없음, 입실·유지 기준, 미인증·CSRF·타인 ID·인원 직접 조작 거절, 승인 대기 회원 거절, 로그아웃 시 즉시 제외, 운영 서버 시뮬레이터 거절, 설정 권한·검증·버전 충돌, 기준 인원 초과 시 정확한 숫자, 재시작 후 유지
- 비콘 앱 로직 검사: 연속 확인 후 입실, 히스테리시스, 신호 끊김 유예, 하트비트, 서버 오류·401·권한 해제·블루투스 꺼짐 처리와 자동 재개, 시뮬레이터 표시
- iBeacon 패킷 해석 JUnit 검사(`cd android && ./gradlew test`)
- 빌드·타입 검사 통과

## 최근 변경

- 예약: 월~일을 한 줄에 표시하고 선택한 날짜의 시간표를 표시합니다. 시작·종료 시간을 30분 단위로 변경하며 본인 예약도 수정할 수 있습니다.
- 각 화면의 상단 제목은 시각적으로 숨기고 접근성용 제목은 유지합니다.
- 입퇴실 시 기존 공과 3D 장면을 유지하고 변경된 사람의 공만 추가·제거합니다.
- GitHub Actions가 빌드·타입·프론트·API·브라우저 검사를 실행합니다. 운영 배포 전에 이 검사들이 통과했는지 확인합니다.

## 무료 호스팅

현재 배포 설정은 Vercel 서울 + Supabase Free 서울 PostgreSQL입니다. 함수가 종료되거나 재배포되어도 데이터는 외부 DB에 남습니다. 초기 접속 지연과 무료 사용량 제한이 있으며, [배포 절차](docs/DEPLOY.md)를 따릅니다. PostgreSQL 접속 비밀 값은 서버에만 보관합니다.
